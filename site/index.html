How to read this

Translate engineering into operating cost.

01 · Baseline

Application logic only

The same counter update and parity decision, executed through delegates without an FSM scheduler, definition lookup, state lookup, or handle lifecycle. This estimates the work the application already needed to do.

02 · Integer

Integer-backed runtime

The same two-state machine using integer FSM, state, and processing-group identities. The difference from baseline estimates the incremental cost of the integer runtime for this workload.

03 · String

String-backed runtime

The same state machine using named FSM states and a named processing group. The difference from integer-backed execution is the measured representation penalty for this workload.

Read the extra columns: standard deviation and error show measurement spread; bytes per operation show allocation pressure; runtime, operating system, architecture, and processor identify the machine that produced the result. A faster mean with noisy samples is not a strong claim.
Evidence, not advertising

What this proves—and what it doesn't.

What this benchmark can prove

For the recorded source commits, runtime, machine, and workload, it can compare the observed cost of integer-backed execution, string-backed execution, and the application-logic baseline. The raw BenchmarkDotNet output remains the audit trail.

What it cannot prove by itself

It does not prove every application will see the same ratio, and it does not prove CiAi's autonomous development loop works. That requires a separate exact-SHA red → diagnostic evidence → bounded repair → green verification demonstration.
